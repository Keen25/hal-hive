## Design — extract a shared, testable binder (reviewers will require this)
`DnsSrvDirectoryDiscovery`'s bind helpers are private/instance. To avoid duplicating the
bind logic and to make the factory testable, **extract the reusable bind path into an
internal seam** that BOTH `DnsSrvDirectoryDiscovery` and `DefaultLdapClientFactory` call.
Suggested shape (adapt to fit cleanly):

- New `internal static class NdjLdapBinder` (in `Service/Source/Service/Domains/` or
  `.../Ldap/`) with:
  - `internal static LdapClientOptions BuildKerberosOptions(string host, int port,
    string login, string password, string domainDnsName, bool useSsl)` — moved/derived
    from `DnsSrvDirectoryDiscovery.BuildKerberosOptions` (realm = domainDnsName.ToUpper()).
  - `internal static ILdapClient BindWithSslFallback(Func<LdapClientOptions,ILdapClient>
    factory, string dc, string login, string password, string domainDnsName, SSLOptions
    ssl)` — the SSL→plain `ConnectAndBind(null)` fallback (moved/derived from
    `KerberosBindWithSslFallback`).
  - Have `DnsSrvDirectoryDiscovery` delegate to this seam (keep its existing behavior &
    tests green — this is a refactor, not a behavior change). If a full move is risky,
    at minimum make the two helpers `internal static` and reuse them; the goal is ONE
    code path, no copy-paste.
- `DefaultLdapClientFactory` (keep it as the `Func<ILdapClient>` `ClientConnections`
  wires into the pools) becomes:
  1. `var domain = Server.Domains.GetCurrentDomain() ?? Server.Domains.GetAllManagedDomains().FirstOrDefault();`
     — if none, throw `InvalidOperationException("NDJ DirSync: no managed domain registered.")`.
  2. `var p = DeletedObjectsNamingContext.LoadDomainParameters(domain.Name);`
  3. **Contract:** if `!p.UseOverrideAccount` (no explicit creds), throw a clear
     `InvalidOperationException` explaining NDJ requires the managed domain to be
     registered with an override/manager account, and that binding under the service
     identity via keytab is a separate follow-up (**#711232**). Do NOT silently fall back.
  4. `string dc = FindDomainControllerName(p.DnsName, p.Login, p.Password, …);` (reuse
     `DnsSrvDirectoryDiscovery`'s discovery — inject/instantiate it with the real
     `IDomainControllerDiscovery` + `opts => new LdapClient(opts)` factory the way the
     rest of the code does; grep how `DnsSrvDirectoryDiscovery`/`Win32DirectoryDiscovery`
     are constructed to match the DI pattern).
  5. `return NdjLdapBinder.BindWithSslFallback(opts => new LdapClient(opts), dc, p.Login,
     p.Password, p.DnsName, p.SslOption);` — a bound `ILdapClient`.
- Keep the real `OneIdentity.Ldap` construction (`new LdapClient(opts)`) inside `Service`
  (it already references the package — `DnsSrvDirectoryDiscovery` uses it).
